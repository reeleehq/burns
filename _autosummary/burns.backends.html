burns.backends#

Pluggable single-clip render backends — the open-closed seam.

A backend turns one (image, BurnsPath, duration) into one video file. They all share the RenderBackend call signature and live in a name-keyed RENDER_BACKENDS registry, so adding a backend (an FFmpeg zoompan fast-path, a future GPU path) never edits the facade — you register_backend() it and select it with backend="…".

The default backend, "pillow", drives a lazy moviepy.VideoClip whose per-frame closure calls burns._frame.sample_frame(), so the whole clip is never materialized in memory and the spec-to-pixel mapping stays in one place. The multi-panel film renderer in burns.render deliberately does not go through this registry — it is a single-pass encode across panels, which a per-clip backend cannot express.

burns.backends.DFLT_BACKEND = 'pillow'#

Still pillow, deliberately. The two backends are NOT pixel-equivalent (measured ~47 dB, dominated by resampler choice rather than by anything either does wrong), so flipping the default would silently change the output of every existing caller. The speed advantage that motivates the ffmpeg path is also still unmeasured — see thorwhalen/burns#12.

burns.backends.frame_count(duration, fps)[source]#

The frames a duration-second clip at fps has, for every backend.

The single definition. It rounds, as the fleet’s other assemblers do, and never returns less than one. moviepy alone would floor (1.99 s at 30 fps is 59 frames), which is why pillow_backend() sizes its clip from this.

Examples

>>> frame_count(9.0, 30), frame_count(1.99, 30), frame_count(0.001, 30)
(270, 60, 1)

int

burns.backends.write_clip(clip, output, *, codec, audio_codec, **write_kwargs)[source]#

clip.write_videofile(output) with burns’ encode defaults, then close it.

MoviePy muxes audio through a temp file it writes to the current directory unless told otherwise (<stem>TEMP_MPY_wvf_snd.<ext>) and removes it only after a successful encode, so a failed one left it wherever its caller ran (reeleehq/reelee#747). Unless the caller places or keeps that file itself (temp_audiofile, temp_audiofile_path, remove_temp=False), it goes in a private directory beside output, removed whatever happens.

Return type:

Path
