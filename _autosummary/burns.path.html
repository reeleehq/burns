burns.path#

The render-agnostic Ken Burns motion spec: BurnsPath.

A BurnsPath is the single source of truth for *how the virtual camera moves over a still image* — pure data, no image, no encoder, no frame count. Its one job is BurnsPath.evaluate(): given a normalized clock time t in [0, 1] it returns the Rect viewport at that instant. That pure t -> Rect primitive is what makes the motion unit- testable without rendering, serializable across the wire as JSON, and re-implementable identically in JS/TS for an in-browser preview.

The model mirrors the professional NLE consensus and Remotion’s interpolate:

  • Keyframes are (t, Rect) waypoints with t in [0, 1]. Two keyframes is the canonical Start/End Ken Burns case; N keyframes is the strict generalization (a hold is two keyframes with equal rects; a single keyframe is also valid and means a static framing).

  • Easing (a CSS timing function) is composed over the geometry — evaluate(t) == geometry(easing(t)) — keeping motion shape orthogonal to motion speed. Default "ease-in-out" (the cinematic norm).

  • output_aspect is metadata: the aspect ratio the render should fill. When it differs from the source image’s AR the renderer cover-crops; when None the output AR equals the image’s. evaluate() never reads it: it only travels with the path. The constructors (BurnsPath.push_in(), ken_burns_path()) do read it, to shape the rectangles they build, and a

    rect’s w / h is in image-normalised units, so they also need the source’s aspect (image_aspect) to get a window that really has the output’s shape.

ken_burns_path() is a convenience generator: it maps a small intent vocabulary (a sequence index, a style, a zoom, a pan) to a cohesive, fully deterministic BurnsPath, so callers animating a sequence of images get non-repetitive motion without hand-authoring rectangles.

class burns.path.BurnsPath(keyframes, easing='ease-in-out', interp='linear', output_aspect=None, version=1)[source]#

Bases: object

A time-parameterized pan/zoom motion over a still image.

Construct it directly from keyframes, or via from_start_end() / push_in() for the common cases, or via ken_burns_path() for deterministic per-index motion across a sequence.

Parameters:

  • keyframes (tuple[tuple[float, Rect], ...]) – a sequence of (t, Rect) waypoints, t in [0, 1], strictly increasing in t. Must have at least one entry; the first t should be 0.0 and the last 1.0 for the whole clock to be covered (out-of-range t clamps to the ends).

  • easing (Union[str, Callable[[float], float], Sequence[float]]) – a CSS timing-function spec (name / cubic-bezier(...) / 4-tuple) or a callable [0,1] -> [0,1]. Default "ease-in-out".

  • interp (str) – geometry interpolation between keyframes. Only "linear" is implemented; the field exists so the spec can carry richer schemes ("catmull-rom", "bezier") without a format change.

  • output_aspect (Optional[float]) – the aspect ratio (width / height) the render should fill. None means “match the source image”.

  • version (int) – spec schema version (for forward-compatible serialization).

Examples

>>> p = BurnsPath.from_start_end(
...     Rect(0, 0, 1, 1), Rect.from_center_zoom(0.5, 0.5, 1.3)
... )
>>> p.evaluate(0.0)
Rect(x=0.0, y=0.0, w=1.0, h=1.0)
>>> round(p.evaluate(1.0).zoom, 4)
1.3
>>> p.duration_keyframes  # number of waypoints
2

evaluate(t)[source]#

The viewport Rect at normalized clock time t in [0, 1].

Applies easing to the clock, then linearly interpolates the geometry at the eased progress. Pure and deterministic: no image, no I/O, no frame count. t outside [0, 1] clamps to the nearest end.

Examples

>>> p = BurnsPath.from_start_end(
...     Rect(0, 0, 1, 1), Rect(0, 0, 0.5, 0.5), easing="linear"
... )
>>> p.evaluate(0.5)
Rect(x=0.0, y=0.0, w=0.75, h=0.75)

burns.path.ken_burns_path(index, *, style='push', zoom=1.1, pan=0.03, easing='ease-in-out', output_aspect=None, image_aspect=None)[source]#

A deterministic BurnsPath for the index-th image of a sequence.

Maps intent to geometry so a sequence of images gets cohesive, non-repetitive motion without hand-authoring rectangles. Per-index deterministic: identical args always return an identical path. Duration is not part of the path — it is a render-time parameter (pass it to burns.ken_burns_video() / burns.ken_burns_film()).

Two styles:

  • style="push" (default) — the “cinematic push”: one slow zoom toward an off-center focal point. Odd indices push in, even indices pull out, so a sequence has visual rhythm without changing direction within a shot. The focal direction rotates through compass octants per index.

  • style="drift" — pure horizontal pan at a constant zoom, alternating direction per index (odd drifts right, even left). zoom is ignored; drift derives its own zoom from pan so the slide is visible.

Parameters:

  • index (int) – the image’s 1-based position in the sequence.

  • style (str) – "push" (default) or "drift".

  • zoom (float) – the zoomed-end magnification (> 1.0) for "push".

  • pan (float) – focal-point offset ("push") or total horizontal travel ("drift"), in [0, 1] image units.

  • easing (Union[str, Callable[[float], float], Sequence[float]]) – CSS timing function or callable. Default "ease-in-out" — the cinematic slow-in/slow-out. Pass "linear" for constant velocity.

  • output_aspect (Optional[float]) – aspect ratio the render should fill (None = match image).

  • image_aspect (Union[float, tuple[float, float], None]) – the source’s width / height. Pass it whenever output_aspect is set (see BurnsPath.push_in()); without it the source is treated as square.

Return type:

BurnsPath

Returns:

A BurnsPath (two keyframes — Start and End).

Examples

>>> ken_burns_path(1).evaluate(0.0)  # odd: push in, starts full
Rect(x=0.0, y=0.0, w=1.0, h=1.0)
>>> ken_burns_path(2).evaluate(1.0)  # even: pull out, ends full
Rect(x=0.0, y=0.0, w=1.0, h=1.0)
>>> ken_burns_path(3) == ken_burns_path(3)  # deterministic
True
burns.path.window_aspect(output_aspect, image_aspect=None)[source]#

The w / h a rect needs, in image-normalised units, to show output_aspect.

A rect’s sides are fractions of the image’s own sides, so a window that is 16:9 on screen over a 16:9 image is the square w == h == 1 in these units. The ratio is output_aspect / image_aspect.

image_aspect=None keeps the original behaviour, which treats the source as square and is only right for a square source; it emits a FutureWarning. Non-positive or non-finite aspects raise. image_aspect may also be the image’s (width, height) size, i.e. PIL’s .size; not NumPy’s .shape, which is (height, width).

Examples

>>> window_aspect(16 / 9, 16 / 9)  # same shape: the full frame
1.0
>>> round(window_aspect(16 / 9, 4 / 3), 4)  # 4:3 source, 16:9 delivery
1.3333
>>> window_aspect(None, 4 / 3)
1.0
>>> round(window_aspect(16 / 9, (1600, 1200)), 4)  # the size works too
1.3333
Return type:

float
